## 프로젝트 전환 경위 — 한글 타이포그래피 벤치마크에서 측정 타당성 연구로

**한 문장:** 모델을 재려고 자(尺)를 만들었는데 자가 고장나 있었다. 그래서
"모델이 얼마나 잘하나"가 아니라 **"그동안 이걸 어떻게 재고 있었나"**가
프로젝트의 주제가 됐다.

### 출발점 vs 지금

| | 원래 계획(설계서 v5) | 지금(v1) |
|---|---|---|
| 정체 | 한글 렌더링 **벤치마크** | 측정 **타당성 연구** |
| 모델 | 5종 비교 리더보드 | 1종(Seedream) — 예시일 뿐 |
| 규모 | 8,580장 생성 | 파일럿 300장 + 합성 이미지 |
| 채점 | OCR 자동 채점 | OCR 자동 50% + **사람 50%** |
| 구조 | Bench(진단) + Forge(처방) | Bench만 |
| 결론 형태 | "모델 A가 B보다 낫다" | "지금까지의 측정 방식은 틀렸다" |

### 네 번의 전환점

**① Route 버그(5단계)** — T1 프롬프트가 T2보다 압도적으로 나쁘게 나와
"프롬프트 설계 문제"로 볼 뻔했으나, 실은 Route 분류기 버그였다. 고치니
300건 중 179건(60%)의 분류가 바뀌었다. *모델 탓으로 보이는 게 파이프라인
탓일 수 있다는 첫 경고.*

**② 판정자 실격(6~7단계)** — 같은 이미지 180장을 사람과 CLOVA에 보였더니
사람 99.4% vs CLOVA 32.8%. 표본을 6배 늘려도 안 바뀌었다. *"측정 도구
문제"가 처음 프로젝트 중심으로 들어옴.*

**③ 글자 크기 오귀속(8단계)** — "CLOVA가 겹받침을 3.3%밖에 못 읽는다 →
겹받침이 어렵다"로 결론지을 뻔했으나, 진짜 원인은 글자 크기였다.
occupancy 0.28→0.10으로 낮추자 실사용 겹받침 인식률이 0%→100%. *판정자의
결함을 모델의 결함으로 오귀속할 뻔한 두 번째 경고.*

**④ 은폐 발견(12~13단계)** — 사람이 "글자가 아니다"라고 표시한 44장을
직접 눈으로 보니 거의 전부 또렷하게 잘 그려진 한글꼴이었다. 감사자 기준은
"윈도우 키보드로 입력 불가능한 형태". 대표 사례: 모델이 `감`의 받침 ㅁ을
**田**(십자획)으로 그렸는데 CLOVA·template_match 둘 다 "감"으로 읽고
정답 처리했다. 파일럿 300장 전수 확인 결과 **21.7%가 유효한 완성형이
아니었다.** *모델의 가장 심각한 실패(존재하지 않는 글자)를 측정 도구가
지운다는 것이 프로젝트의 새 주제가 됨.*

### 그 뒤 확인한 것

- **CLOVA만의 문제가 아니다(17단계)** — 아키텍처가 다른 EasyOCR도 은폐율이
  비슷했다(76.9% vs 83.1%). 둘이 답한 44건 중 77%는 서로 다른 글자로
  스냅함 — 사전 공유가 아니라 "반드시 하나는 골라야 한다"는 구조 자체가
  원인.
- **사람도 만능은 아니다(14단계)** — "유효한 글자인가"(이진)는 α=0.942로
  잘 일치했지만 "망가진 한글이냐 아예 한글이 아니냐"(세부 분류)는
  α=0.52로 사람끼리도 못 나눴다. → 신뢰 가능한 질문만 지표로 채택.
- **우리 자신의 주장도 두 개 틀렸다(19단계)** — "OCR이 겹받침 격차를
  과장한다"(틀림: 진실·CLOVA 둘 다 −21.1%p로 일치), "은폐가 점수를
  부풀린다"(거의 없음: 72건 중 3건). 실제로 무너지는 건 차이가 아니라
  **수준**이었다 — 세 축 모두 일정하게 약 26%p 과소평가.

### 잃은 것과 얻은 것

| 잃은 것 | 얻은 것 |
|---|---|
| 모델 순위 리더보드(RQ6) | 재현 가능한 방법론적 발견 |
| Forge(처방 절반) | 사람 검증 골드셋 300장(α=0.942) |
| 완전 자동 채점 | 검증된 판정 프로토콜(편향 −0.8%p) |
| "한글 렌더링 벤치마크"라는 간판 | **다른 언어·다른 벤치마크에도 적용되는 주장** |

원래 목표대로 갔다면 "Seedream이 한글을 62% 그린다"는, 모델 버전이 바뀌면
곧 무의미해질 숫자가 남았을 것이다. 지금은 중국어·일본어·아랍어 렌더링
평가(Qwen-Image, AnyText 등 주요 논문 전부가 OCR 채점을 쓴다)에도 그대로
적용되는 문제 제기가 남는다.

## 이 벤치마크로 할 수 있는 것 (쉬운 요약)

한 문장: **"이미지 생성 모델이 한글을 그릴 때 어디서 무너지는지"를 자모
단위로 진단하고, 그 진단을 흐리는 판정자 문제까지 함께 보고한다.**

### 답할 수 있는 질문 4가지

| # | 질문 | 어떻게 답하는가 |
|---|---|---|
| 1 | **"이 모델이 그린 게 애초에 한글이긴 한가?"** | 유효 완성형 생성률. 실측 결과 Seedream 출력의 **21.7%가 키보드로 입력조차 불가능한 글자**였다 |
| 2 | **"한글을 그렸다면, 지시한 그 글자인가?"** | 유효 완성형 중 타깃 일치율 |
| 3 | **"어떤 구조에서 더 많이 무너지는가?"** | 18셀(모음 2 × 종성 3 × 초성군 3) 비교. 겹받침이 단순종성보다 15.8%p 나쁨(사람 기준 실측) |
| 4 | **"초성·중성·종성 중 어디가 약한가?"** | 자모 위치별 오류율. 순서(초성>중성>종성)는 검정 가능, 절대값은 사람 검증분에서만 |

### 왜 기존 방식으로는 안 되는가 (= 이 프로젝트의 기여)

OCR로 채점하면 **위 1번 질문이 통째로 사라진다.** OCR은 "없는 글자"를 만나도
가장 비슷한 진짜 글자로 바꿔 읽어버리기 때문이다. 실제 사례:

> 모델이 `감`의 받침 ㅁ을 **田**(안에 십자획)으로 그렸다. 사람은 "이건 입력
> 불가능한 글자"라 판정했지만, CLOVA와 template_match **둘 다 `감`으로 읽고
> 정답 처리**했다.

즉 **모델의 가장 심각한 실패(존재하지 않는 글자를 그림)를 판정자가 은폐한다.**
이 은폐율 자체를 측정해서 보고하는 것이 JAMO v1의 핵심이다.

### 쓸 수 있는 것 / 없는 것

| | |
|---|---|
| ✅ **구조 비교** | "겹받침이 단순종성보다 Y%p 나쁘다" — 자동 판정 포함 가능 |
| ✅ **절대 정확도** | 단, **사람 검증분(Gold split)에서만** |
| ✅ **판정자 은폐율** | 방법론적 기여. 다른 벤치마크에 그대로 이식 가능 |
| ❌ **모델 순위 리더보드** | 단일 모델만 평가하므로 v1에 없음 |
| ❌ **완전 자동 채점** | 사람이 절반(50%)을 봐야 함. 이것이 실측으로 확인된 하한 |

## 공개 프레이밍 재정의 — "벤치마크"가 아니라 "측정 타당성 연구"

*2026-08-11, 17단계 착수 직전 결정. 근거: Seedream 본배치 전 공개 반응
가능성을 재검토한 결과.*

### 벤치마크로 내면 반응을 못 얻는다

| 문제 | 이유 |
|---|---|
| 단일 모델 | 벤치마크가 아니라 사례연구로 읽힌다 — 리뷰어 1순위 지적 |
| 사람 50% 필요 | HF에서 반응을 얻는 조건은 "pip install하고 바로 돌아가는 것". 감사자 고용이 필요하면 아무도 안 씀 |
| 리더보드 없음 | 재방문 동기가 없음 |
| 모델 수명 | Seedream 버전이 바뀌면 숫자가 곧바로 무의미해짐 |

"JAMO: 한글 렌더링 벤치마크"로 내면 진짜 벤치마크(Qwen-Image 계열 등)와
비교당하고 진다.

### 방법론 논문으로 내면 반응을 얻을 수 있다

핵심 주장을 벤치마크 수치가 아니라 **측정 타당성 문제**로 바꾼다:

> **인식 기반 판정자(OCR·형태매칭 불문)는 잘못 그려진 글자를 조용히
> "고쳐서" 읽는다. 따라서 텍스트 렌더링을 OCR로 채점하는 모든 벤치마크는
> 모델 품질을 체계적으로 과대평가한다.**

이 주장은 한글 국한이 아니다 — 중국어·일본어·아랍어·데바나가리 렌더링
평가(Qwen-Image, AnyText 등 주요 논문 전부가 OCR 채점을 쓴다)에 그대로
적용된다. 선례: Northcutt et al. *"Pervasive Label Errors in Test Sets
Destabilize ML Benchmarks"* — 새 모델도 새 데이터셋도 없이 순수 측정
타당성 비판만으로 큰 반향을 얻었다. 구조가 동일하다.

이 프레이밍에서는 이전에 약점으로 봤던 것들이 논거로 바뀐다:

| 이전 프레이밍(약점) | 새 프레이밍(논거) |
|---|---|
| 단일 모델이라 초라함 | 모델은 예시일 뿐 — 기여는 판정자 축에 있음 |
| 사람 50% 필요 = 자동화 실패 | "이 정도 사람 개입 없이는 제대로 못 잰다"는 것 자체가 결론 |
| §14.2 공식 점수 하한 미달(85%) | 하한 미달 자체가 보고할 결과 |

### 이 프레이밍이 요구하는 것 — 판정자 일반화

**현재 증거는 CLOVA(한국 상용 OCR) 1종 + 자체 template_match뿐이다.**
그런데 실제 렌더링 논문들은 PaddleOCR/EasyOCR 계열을 쓴다(설계서 §8.1도
원래 OSS OCR을 Primary로 하려다 CLOVA 키가 먼저 있어 건너뛴 상태였다).

리뷰어의 첫 질문: *"그건 네이버 OCR 얘기고, 우리가 쓰는 PaddleOCR도
그러냐?"* — **지금은 답할 수 없다.** 이게 17단계의 착수 이유다.

**우선순위 재조정:** Seedream 표본을 늘리는 것(구 5번 작업)보다 **판정자
쪽 일반화**가 훨씬 저렴하고 훨씬 값지다 — 이미 사람 라벨이 붙은 300장을
그대로 재사용할 수 있다(API 비용 0, Seedream 신규 호출 없음).

```
1순위  OSS OCR 2~3종 교차검증        비용 0, 반나절   ← 완료(17단계), 아래 참고
2순위  파일럿 300장 v3 재채점         비용 0            ← 완료(18단계), 아래 참고
3순위  표본 보강 720장                Seedream 비용
선택   Qwen-Image 추가 (오픈 웨이트)   GPU 비용, 범위 재확장 — 보류
```

### 2순위 결과 — 첫 인용 가능한 채점표(18단계)

`scripts/rescore_pilot_v3.py`로 확정 프로토콜을 파일럿 300장에 적용했다.

| Primary 지표 | 값 |
|---|---|
| 유효 완성형 생성률 | **76.0%** |
| 타깃 일치율 \| 유효 완성형 | **71.5%** |

종성유형별로 **겹받침은 타깃 일치율뿐 아니라 유효 완성형 생성률 자체가
24.5%p 낮다**(no_T 86.7% vs cluster_T 62.2%) — 12~13단계의 정성적 관찰을
확정 프로토콜로 처음 정량화했다.

**주의 — Gold 부분집합(사람 판정 172건)만 따로 보면 well-formed rate가
58.1%로 훨씬 낮다.** 모순이 아니라 confidence 게이트가 malformed 글자를
우선적으로 사람에게 보내는 라우팅 성질 때문이다(16단계 자기교정 기전).
Gold 부분집합은 population 추정치가 아니므로 13단계의 78.3%(전체 300장
순수 사람 라벨)와 직접 비교하지 않는다. 반대로 Silver 128건은 verdict가
전부 VALID인데, 이는 CLOVA가 조용히 스냅한 무효 글자(15단계 실측 6.8%)를
그대로 포함하기 때문 — **은폐 현상이 이 프로젝트 자신의 결과표 안에서도
재현**된다. 그래서 Primary 1 전체 수치(76.0%)에는 `MEASURED_BIAS_PP`가
항상 병기돼야 한다.

### 1순위 결과 — 주장이 일반화됨(17단계)

EasyOCR(오픈소스, CRNN 기반, CLOVA와 아키텍처·학습데이터 무관)로 파일럿
300장을 재검증한 결과, **은폐율이 CLOVA와 거의 같았다**(CLOVA 76.9% vs
EasyOCR 83.1%, 무효 판정 65건 기준). 더 강한 증거로, 둘 다 답을 낸 44건
중 **77.3%는 서로 다른 글자로 스냅**했다 — 사전 공유가 아니라 "유효 음절
집합 중 하나를 반드시 골라야 한다"는 **폐쇄형 인식 구조 자체**가 원인임을
시사한다. 이로써 핵심 주장을 "CLOVA의 문제"가 아니라 "**인식 기반 판정자
(최소 두 개의 독립 아키텍처에서 재현됨)의 구조적 문제**"로 일반화할 수
있는 최소 증거를 확보했다. 상세: `docs/PROGRESS.md` 17단계.

## 목표 (한 문장)

> **한글 렌더링을 OCR로 채점하면 (a) 절대 수준을 최대 4배 과소평가하고,
> (b) 어떤 OCR을 쓰느냐에 따라 구조적 효과 크기가 2배 달라지며, (c) 가장
> 흔한 실패 유형("존재하지 않는 글자")을 원리적으로 보고할 수 없다**는 것을
> 정량화하고, 사람 이진 검증(α=0.942)에 기반한 대안 프로토콜을 제안한다.

절대 정확도 리더보드가 아니라 **측정 타당성 연구**다. 이렇게 두면 설계서
§14.2의 공식 점수 하한(사람–판정자 일치율 85%) 미달이 프로젝트의 약점이
아니라 **보고할 결과**가 된다.

**헤드라인으로 쓰면 안 되는 것:** "겹받침이 어렵다" — 상식이며 기여가
아니다. 기여는 결론이 아니라 **그 결론에 이르는 측정 경로의 검증**에 있다
(19단계).

## 범위

### 포함

- **모델**: Seedream 1종 (`dola-seedream-5-0-pro-260628`)
- **셀**: 18셀 (2모음 × 3종성 × 3초성군) — 설계서 §6.2 그대로
- **템플릿**: T1 / T2 (`PROMPT_SPECS.yaml` freeze)
- **판정**: `judging_protocol.py` (아래 규칙)
- **사람 판정**: 이진 유효성(필수) + 유효 시 전사

### 판정 규칙 (전부)

```
confidence >= 0.80 (CLOVA inferConfidence)
  AND 초성군 != tense_O (ㄲㄸㅃㅆㅉ)        →  CLOVA 판독 그대로 채택
그 외 (검출 실패 포함)                       →  사람 판정
                                                1) 유효 완성형인가 (이진)
                                                2) 유효하면 전사
```

| 항목 | 실측값 | 비고 |
|---|---|---|
| 사람 큐 | **50.0%** | 자동화의 실측 하한 |
| 전체 편향 | **−0.8%p** | 항상 사람보다 낮거나 같음(방향 고정) |
| 셀 축별 편향 변동폭 | 종성 1.5 / 모음 0.5 / 초성군 1.9%p | 세 축 전부 기준(≤2.5%p) 통과 |
| 겹받침−단순종성 격차 복원 오차 | −1.6%p | 구조 비교 신뢰 근거 |
| 자모 위치 기울기 과장 | +3.3~3.9%p | 순서는 보존, 절대값은 Gold에서만 |
| 은폐(무효를 정답 처리) | 자동 채택 133장 중 0건 | n 작음 — 95% 상한 약 2.2% |

**`tense_O` 제외 이유:** 이 구간에서만 confidence의 자기교정이 깨진다 —
자동 채택 구간 CLOVA↔사람 불일치율 **47.4%**(simple_O 4.5%, aspir_O 21.7%).
쌍자음 음절의 실사용 빈도가 낮아 8단계의 희귀도 편향이 재현되는 것으로 보인다.
**단 이 규칙은 n=63 in-sample 적합이므로 표본 보강 시 재검증한다.**

## 지표

**성공 기준은 2단계다.** 한 이미지가 "성공"이려면 둘 다 통과해야 한다:

```
1단계  유효 완성형인가      = 11,172 완성형 집합의 원소인가 (= 키보드로 입력 가능한가)
2단계  타깃과 일치하는가    = 프롬프트로 지시한 그 글자인가
```

1단계를 빼면 판정자가 malformed glyph를 가장 가까운 유효 음절로 스냅한
것을 성공으로 셀 수 있다 — 이것이 이 프로젝트가 발견한 핵심 실패 모드다.

```
Primary 1  유효 완성형 생성률 (셀별)      ← 1단계. 사람 이진 라벨, α=0.942. 절대값 주장 가능
Primary 2  타깃 일치율 | 유효 완성형      ← 2단계. Primary 1 통과분이 분모
Primary 3  판정자 은폐율                   ← 판정자가 무효 글자를 유효로 답한 비율
                                            (= 이 프로젝트의 방법론적 기여)

Secondary  자모 위치별(초/중/종성) 오류율 — **조건부로만**:
           · 순서(초성>중성>종성)는 프로토콜로 검정 가능(H4 방향 검정)
           · 기울기는 +3.3~3.9%p 과장됨 → **절대값은 Gold split에서만** 인용
           · Conditional(유효만, 분모 212) / Unconditional(무효는 3위치 전부
             오류, 분모 256)을 §8.5.1대로 반드시 병기 — 무효 글자의 자모
             분해는 판정자가 스냅한 결과라 허구이므로 단독 인용 금지

폐기       절대 정확도 리더보드, overgen_rate, malformed/non_hangul 세부
```

**설계상의 이점:** 신뢰 가능한 사람 판정(이진)이 동시에 **가장 싼** 판정이다.
전사가 필요 없어 문항당 몇 초면 끝나고, 희귀 음절 전사에서 사람이 흔들리던
문제(7단계에서 유일한 오답이 최난이도 셀이었음)를 구조적으로 피한다.

**병기 의무:** 자동 판정이 섞인 수치는 `judging_protocol.MEASURED_BIAS_PP`
(0.0 ~ −1.5%p, 전체 −0.8%p)를 항상 함께 보고한다. 절대 정확도는 **사람 전수
판정 구간(Gold)으로만** 주장한다.

### 사람 판정의 신뢰도는 세 단계로 갈린다

이 구분이 지표 설계 전체를 결정한다 — 신뢰 가능한 질문만 1차 지표로 쓴다.

| 판단 | 신뢰도 | 용도 |
|---|---|---|
| "유효 완성형인가" (이진) | **α = 0.942** | Primary 1 — 절대값 주장 가능 |
| "그래서 무슨 글자인가" (전사) | **100%** (23/23, 유효 판정 건 한정) | Primary 2 |
| "malformed냐 non_hangul이냐" | α = 0.52~0.58 | **exploratory only** |

## 라벨 체계 (확정)

```
Primary   valid_syllable / invalid          ← α=0.942. 이것만 1차 기준
Secondary invalid 내부: malformed / non_hangul / multi_syllable / no_text
          ← exploratory. α 0.515~0.576이므로 신뢰도 낮음을 반드시 명시
```

2번째 감사자의 α는 **이진 기준으로 산출**하고, 세부 분류 α는 참고값으로만
병기한다. 5분류로 α를 내면 신뢰할 수 있는 축까지 경계 불일치에 끌려 낮아진다.
